Phase 4 Tool Layer MVP 审核页

这一页帮助你快速审核 Phase 4：我们不是在做真实 ADaM 生成，而是在给后续 LangGraph 节点装一层稳定、可替换、可审计的工具接口。

1. Phase 4 一句话目标

Phase 4 的目标是把“具体干活的能力”从 Graph 节点里抽出来：读文件、扫 study、算 hash、写 manifest、调用 LLM、跑 R，都先通过工具接口。

简单说：Graph 负责决定下一步做什么；Tool 负责把这件事具体做出来。

2. 当前实现流程图

StudyGraph / DatasetGraph
  -> ConfigLoader      读取本次 run 的策略
  -> StudyInputScanner 扫描 input_sdtm / reference_adam / input_spec / legacy_code
  -> SDTMReader        读取 CSV 的列名、行数、少量样例
  -> ArtifactStore     计算 sha256，写 runs/{run_id}/audit/manifest.json
  -> LLMClient         Phase 4 只接 MockLLMClient，不接真实外部 API
  -> RRunner           Phase 4 只接 StubRRunner，不启动真实 R 进程

3. 你需要重点看的文件

文件 它负责什么 审核重点
src/adam_agent/tools/artifacts.py 注册文件、计算 sha256、写 canonical manifest。 manifest 路径是否接受：runs/{run_id}/audit/manifest.json。
src/adam_agent/tools/study_inputs.py 扫描 study 文件夹，把输入变成结构化 index。 .sas 是否只当 legacy code，不当数据。
src/adam_agent/tools/sdtm_reader.py 轻量读取 CSV metadata、row count、sample rows。 .sas7bdat 现在是否可以明确暂不解析，而不是假装成功。
src/adam_agent/tools/config.py 读取 run config，归一化 LLM 数据暴露策略。 是否沿用 Phase 2 的 LLMExposureConfig，不另搞一套 schema。
src/adam_agent/llm/model_registry.py 管理 provider/model 能不能用。 OpenAI/Anthropic 现在是否应该明确未实现，避免误以为能跑。
src/adam_agent/llm/clients.py 定义 LLMClient 协议和 mock client。 返回值是否包含 response text 和审计记录，而不是裸字符串。
src/adam_agent/tools/r_runner.py 定义 R 执行边界和 stub runner。 Phase 4 不依赖本机 R，也不启动真实 R subprocess。
tests/test_tools_phase4.py 验证上述工具边界。 是否覆盖了“不需要 API key、不需要网络、不需要真实 R”。

4. 关键设计判断

判断 当前实现 我的建议
Phase 4 要不要接真实 OpenAI/Anthropic？ 不接。只支持 mock/mock-model。 接受 先把接口稳定下来，避免 API key 和 provider 细节干扰架构。
用户说的 gpt-5.5 这类模型怎么办？ openai/gpt-5.5 会明确报未实现，不会偷偷 fallback 到 mock。 接受 这样不会造成“以为测过真实模型”的假象。
Mock LLM 是否还要审计？ 要。会产生 prompt/response artifact id 和 hash。 接受 mock 也走真实审计形状，后面替换 provider 更稳。
.sas7bdat 现在是否读取？ 识别格式，但 profiler 返回 not_implemented_yet。 可接受 Phase 5/后续再接 R/haven 或 pyreadstat。
R 沙盒现在是否真实跑？ 不跑。StubRRunner 只返回结构化成功/失败。 接受 真实 sandbox 是 Phase 5 的复杂点。

5. 现在已经能保证什么

  • 工具模块可以 import。
  • Mock LLM 不需要 API key、网络或外部 provider。
  • Mock LLM 仍然产生 LLMCallRecord，包含 provider、model、exposure mode、prompt hash、response hash。
  • Study input scanner 返回结构化对象，而不是简单 path list。
  • Artifact manifest 写到固定 run audit 路径。
  • CSV profiler 能读列名、行数和限定数量的样例行。
  • .sas 不会被当成 SDTM 数据。
  • R runner 结果是结构化对象，有 stdout、stderr、exit code。

6. 现在明确不能保证什么

  • 不能生成真实 ADSL。
  • 不能调用真实 OpenAI、Anthropic 或 OpenAI-compatible endpoint。
  • 不能读取真实 .sas7bdat 内容。
  • 不能执行真实 R 代码。
  • 工具还没有接入 Phase 3 的 StudyGraph/DatasetGraph。
这些不是 bug，是 Phase 4 的有意边界。真正跑 ADSL 的闭环应该进入 Phase 5。

8. Windows 临时目录问题

最初 Phase 4 测试用 tempfile.TemporaryDirectory()，在这个 Windows 环境下创建的临时子目录出现写入/清理权限错误。

已改为项目内 .tmp_tests/ 固定测试根目录，并加入 .gitignore。这只影响测试稳定性，不影响产品逻辑。

9. 我建议你怎么快速审核

  1. 先看本页第 4、5、6 节，确认边界是否符合你的预期。
  2. 再看 src/adam_agent/llm/model_registry.py 和 clients.py，确认“不假装支持真实 provider”。
  3. 再看 src/adam_agent/tools/study_inputs.py，确认 study 输入扫描的结构是否直观。
  4. 最后看 tests/test_tools_phase4.py，确认测试覆盖的是工具边界，而不是过早进入真实业务逻辑。
