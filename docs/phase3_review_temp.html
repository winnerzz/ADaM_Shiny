Phase 3 LangGraph Skeleton 设计审核页

这一页把 Phase 3 的核心设计、三个子 agent 审查意见、已完成实现、测试结果和最终收口状态集中展示。

1. Phase 3 一句话目标

已做一个可运行的 LangGraph 空骨架：StudyGraph 负责编排多个 ADaM dataset，DatasetGraph 负责单个 dataset 的 stub 流程。

这个阶段不做真实 LLM、R 沙盒、SDTM 解析或真实 ADSL 生成。

2. 最终认可的业务流程

StudyGraph
  -> plan dependency order
  -> run ADSL first
  -> if ADSL succeeds:
       dispatch ADAE / ADLB / ADCM as downstream tasks
  -> if ADSL fails:
       mark downstream datasets as blocked
  -> collect dataset-level summaries
  -> write study-level audit manifest stub
关键修正：ADSL 不是和 ADAE 平级并行。ADSL 是 MVP 的 foundation dataset，下游 dataset 只能在 ADSL 成功后分发。

3. 三个子 Agent 审查结论

审查角色 主要意见 我的判断
LangGraph 架构审查 StateGraph、subgraph、Send、thread_id、避免混用静态边和动态路由的理解基本准确。需要明确父图管理 checkpointer，dataset id 不要写死到 checkpoint_ns。 采纳
临床 ADaM 流程审查 不能把 ADSL 和 ADAE 当成完全平级任务。ADSL 应先行；ADSL 失败时下游应 blocked/skipped。 采纳
工程落地审查 缺少 langgraph 依赖；Phase 2 state_model 里的 checkpoint_ns 建议与 Phase 3 设计冲突；需要明确 StudyGraphState/DatasetGraphState 和 reducer。 采纳

4. 已经修正的点

  • 把 Phase 3 流程改成 ADSL 先行，下游 dataset 后分发。
  • 修复只请求下游 dataset 时绕过 ADSL 的漏洞：例如只请求 ADAE 时会自动补入 ADSL foundation task。
  • 新增 ADSL 失败时下游 blocked_by_adsl 的测试目标。
  • 明确 checkpoint_ns 是 LangGraph 内部命名空间，不是业务 dataset id。
  • 修正 docs/state_model.md 中旧的 checkpoint_ns = "{dataset}" 建议。
  • 在 pyproject.toml 中加入 langgraph>=0.6,<1 依赖。
  • 明确 runtime state 命名为 StudyGraphState 和 DatasetGraphState。
  • 要求 dataset_results 使用 reducer，避免并行结果互相覆盖。
  • 明确当前 Phase 3 验证的是 study-level checkpoint history，不宣称已经验证嵌套 subgraph checkpoint 继承。
  • 给 code/spec repair route 加入 max_repair_attempts 上限保护。
  • roadmap 已改为 Phase 3 skeleton implemented and tests passing。
