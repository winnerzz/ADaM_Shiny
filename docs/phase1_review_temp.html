3. MVP 产品边界

第一版做什么

  • 本地 study 文件夹输入。
  • 读取 SDTM DM 和 EX。
  • 可选读取 ADSL spec。
  • 可选读取 reference ADSL。
  • 可选读取 define.xml。
  • 可选读取 legacy ADSL SAS 程序。
  • 生成 ADSL lineage、draft spec、approved spec、R code、output、validation、audit。

第一版不做什么

  • 不一次生成所有 ADaM。
  • 不做完整 P21 验证。
  • 不做完整 CDISC RAG 系统。
  • 不做生产级用户权限。
  • 不做完整 UI。
  • 不宣称 regulatory-grade validation。

4. Study 文件夹结构

当前合同规定，输入和 run 输出分开。canonical 输出只放在每次 run 目录里。

studies/
  {study_id}/
    input_sdtm/
      dm.csv 或 dm.sas7bdat
      ex.csv 或 ex.sas7bdat
    input_define/
      define.xml
    input_spec/
      adsl_spec.csv 或 adsl_spec.json
    reference_adam/
      adsl.csv 或 adsl.sas7bdat
    legacy_code/
      ADSL.sas
    runs/
      {run_id}/
        lineage/
        specs/
        code/
        outputs/
        validation/
        compare/
        audit/
已修正：顶层 outputs/ 和 audit/ 不再作为 canonical 输出目录，避免和 runs/{run_id} 冲突。

5. 没有 Spec 时如何生成 Draft Spec

核心原则：Reference ADaM 可以帮助发现目标变量，也可以验证候选推导逻辑，但不能单独决定推导逻辑。

证据优先级 证据 主要用途
1Existing ADaM spec变量、标签、类型、推导逻辑
2Legacy SAS AD program推导逻辑、join 顺序、过滤条件、边界情况
3SAP / protocol / TFL shells分析人群、endpoint、窗口期、治疗期定义
4define.xmlmetadata、label、codelist、dataset 定义
5Reference ADaM dataset目标变量形态、类型、取值模式、最终比较对象
6SDTM profiles可用源变量、日期范围、缺失、key
7CDISC IG标准变量和通用约定
8Company standards公司内部实现习惯
9Built-in templates弱证据时的常见 ADSL starter pattern
需要你接受的关键判断：Reference ADSL 如果和某个候选规则算出来一致，可以提高置信度；但如果没有 spec、legacy code、SAP/protocol 或 define.xml 支撑，复杂变量仍然要人工 review。

6. ADSL 第一版最小边界

第一版不是完整 submission-ready ADSL，而是最小可验证骨架。

变量/逻辑 来源 自动化态度
USUBJID DM.USUBJID 高置信度，通常可 silent pass。
人口学变量，例如 AGE/SEX/RACE DM 直接映射可 silent pass，派生或重编码需记录。
治疗标签/治疗组 DM 或 study evidence 如果 ARM/ACTARM 逻辑不清楚，需要 review。
TRTSDT min(EX.EXSTDTC) 候选规则 可以 draft，但如果 study 规则不同要 review。
TRTEDT max(EX.EXENDTC) 或 max(EX.EXSTDTC) EXENDTC 缺失时需要标注假设。
SAFFL 是否存在 EX 记录 demo 可用简单规则；正式规则需要 SAP/spec 支撑。

这些暂不自动强推：ITTFL、EFFFL、baseline flags、analysis periods、endpoint-related flags、复杂 visit/window 逻辑。

7. Approved Spec 审批边界

子 agent 指出一个风险：如果没有审批记录，adsl_approved_spec.json 可能只是 draft spec 的复制品。现在合同已修正。

{
  "approval_mode": "human | silent_pass | demo_only_no_review",
  "approved_by": "user id, system rule, or demo config",
  "approved_at": "ISO-8601 timestamp",
  "reviewed_variables": ["USUBJID", "TRTSDT"],
  "unresolved_assumptions": [],
  "source_draft_spec_hash": "sha256:..."
}
代码生成必须基于 approved_spec。如果没有人工 review，也必须写明是 silent_pass 或 demo_only_no_review。

8. LLM 数据暴露模式

模式 能发给 LLM 什么 当前口径
metadata_only 变量名、类型、label、缺失率、unique 摘要、日期范围。 真实/未知临床数据默认模式。
demo_rich_context metadata + 样例行 + 变量分布 + reference ADSL 样例。 当前 processed demo 可用，但必须 run config 显式声明。
full_data_allowed 更大数据片段或小表全量。 保留用户批准调试模式；用户批准即用户负责，必须写入 audit。 
demo_rich_context requires:
  data_classification = processed_demo
  external_api_allowed = true

10. 仍需你审核确认的点

  1. ADSL 最小变量集合是否够用： 当前建议从 USUBJID、人口学变量、治疗标签、TRTSDT、TRTEDT、SAFFL 开始。
  2. Spec 缺失时的证据优先级是否接受： legacy SAS / SAP / protocol / define.xml 优先于 reference ADaM 的推导解释。
  3. full_data_allowed 责任口径是否接受： 用户批准调试时可以更宽松外发，但必须进入 audit。
  4. 是否允许 Phase 1 完成并提交： 如果同意，下一步提交 docs: add phase 1 product contracts。

SAS 边界补充

  • .sas7bdat 是 SAS 数据表，R sandbox 可以通过 R 包读取。
  • .sas 是 SAS 程序。MVP 中只作为文本证据用于 lineage/spec drafting，不由 R sandbox 直接执行。
  • 未来如果要直接执行 SAS 程序，需要单独集成 SAS runtime 或做 SAS-to-R 转译。
如果你想更快进入 Phase 2，可以先接受当前 Phase 1 合同，把 ADSL 精确变量清单留到 Phase 2 state model 或 Phase 1.5 里继续细化。
